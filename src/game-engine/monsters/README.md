# C3C generic Monster runtime

`prepareProductionMonsterAction(environment, request)` selects exclusively from the frozen C3B
compact registry and returns a serializable `READY` plan or an explicit disposition. An explicit
definition/action can also be planned with `planProductionMonsterAction`. Eligibility and miniature
supply are deliberately outside this boundary. The rule version travels on each plan.

The environment supplies current unit snapshots and exact spatial distances. The kernel preserves
the C3B-cited Ruins area target selection and stance/id tie contract, with a separate global
living-Hero selector for `ALL_HEROES`. Exact printed ranges are validated before any dispatch;
the kernel never moves a Monster toward range. No random facts are generated by the kernel.
The pinned attack d10 is shared across targets, as in the existing staged attack pipeline.

`executeProductionMonsterAction(adapter, request)` provides synchronous isolated execution. Its
adapter must preflight the complete operation sequence and its random/choice dependencies before
mutating state. Attack callbacks own printed attack resolution, damage, protection, riposte and
reactions; effect callbacks bind existing damage, condition, healing, shuffle, disease and other
transaction primitives. Self-wounds go through the existing damage helper as non-enemy damage,
once per action, even on misses. `PRINTED_EFFECT` retains its effect slot; `AFTER_ACTION` moves
only that explicitly delayed operation after all target resolutions. Other self effects preserve
the accepted self-before-attack contract. On-hit effects require a surviving target.

For C3D live battles, consume `READY` operations through the existing staged attack and saved-choice
pipeline. Do not use the synchronous adapter across unresolved reaction/placement choices. C3D owns
the continuation cursor, causal event IDs, choice candidates, lifecycle and injected adapter RNG.
It must not rebuild action definitions or silently skip effects. The C3C synthetic adapter lives
under `src/audit/` and is not an encounter or campaign-spawning implementation.

Timed Protection is a separate list of duration tokens, never an edit to a printed profile.
Effect callbacks call `grantTimedProtection`; the owning lifecycle calls `expireTimedProtection`
at its unit condition-duration boundary. `hasRuntimeProtection` combines base Protection with
unexpired grants for the existing enemy-damage protection calculation. Repeated grants retain
independent durations; expiry affects only the supplied unit.

The single capability guard runs before environment reads, dice validation or adapter calls for an
action. Any deferred effect/requirement blocks the entire action with its existing deferred IDs.
The seven blocked actions, source semantics and definition-level eligibility issues remain frozen.

Validation is limited to C3B verification, C3C tests/verifier, typecheck and build. C3D will bind
production Dungeon encounters; browser, save/replay acceptance and historical regression belong
to C3E.
